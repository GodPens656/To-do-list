# To-do list — Дневник

Приложение для дел и заметок на Python с интерфейсом Flet. Поддерживает
локальное хранение, аккаунты и синхронизацию через Dropbox.

## Возможности

- Дела и заметки в группах, отметка выполнения, редактирование и удаление.
- Общие группы дел и заметок: создание по паролю и подключение других устройств.
- Отложенные дела и повторения по расписанию.
- Вложения к делам и заметкам: просмотр изображений и скачивание любых файлов.
  Прикрепляйте и убирайте файлы в форме создания или редактирования дела или заметки
  (до 10 МБ на файл и до 20 МБ на запись). Вложения сохраняются вместе с записями,
  включая синхронизацию и резервные копии; скачивается исходный файл.
  Для авторизованных пользователей действует общий лимит вложений 10 МБ
  на аккаунт, включая заметки, повторяющиеся и отложенные дела. Вложения, перенесённые
  из шаблона в созданные по нему дела, учитываются один раз.
- Светлая и тёмная темы, настройка цветов, шрифтов и иконок.
- Пароль на вход в приложение.
- Шифрование локальных и облачных данных с помощью AES-256-GCM.
- Автоматические и ручные резервные копии в облаке.
- Настольный интерфейс и веб-режим с хранением данных посетителя в браузере.

## Установка и запуск

Проверено в Windows с Python 3.13.5. Версии основных зависимостей закреплены
в `requirements.txt` по рабочему окружению проекта.

После клонирования репозитория откройте терминал в его корневой папке:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item secret.example.py secret.py
```

Откройте `secret.py` и заполните значения:

| Настройка | Назначение |
| --- | --- |
| `DROPBOX_ACCESS_TOKEN` | Краткоживущий токен для быстрой проверки; при refresh token оставьте пустым. |
| `DROPBOX_APP_KEY` | App key приложения Dropbox. |
| `DROPBOX_REFRESH_TOKEN` | Токен для постоянной синхронизации с автоматическим обновлением доступа. |
| `DROPBOX_APP_SECRET` | Не нужен для PKCE; нужен для токена, полученного обычным OAuth code flow. |
| `ENCRYPTION_KEYWORD` | Прежняя секретная фраза для шифрования и расшифровки данных. |

### Получение ключа и токенов Dropbox

1. Откройте [Dropbox App Console](https://www.dropbox.com/developers/apps) и нажмите **Create app**.
2. Выберите **Scoped access**, **App folder**, задайте имя приложения и создайте его.
3. Во вкладке **Permissions** включите `files.metadata.read`, `files.content.read`
   и `files.content.write`, затем нажмите **Submit**.
4. Во вкладке **Settings** скопируйте **App key**. Для разовой проверки можно
   нажать **Generate** в разделе **OAuth 2 → Generated access token** и записать
   результат в `DROPBOX_ACCESS_TOKEN`. Сам App key доступ к файлам не даёт.
5. Для постоянной работы выполните из корня проекта:

   ```powershell
   python configure_dropbox.py
   ```

   Введите App key, откройте выданную ссылку, разрешите доступ и вставьте код
   авторизации. Скрипт использует PKCE и offline access; App secret и redirect URI
   не нужны. Если в консоли есть настройка **Allow public clients (Implicit Grant
   & PKCE)**, разрешите PKCE. Скопируйте выданные строки `DROPBOX_*` в существующий
   `secret.py`, сохранив `ENCRYPTION_KEYWORD`, и перезапустите дневник.

Все значения `DROPBOX_*` можно задать переменными окружения, они имеют приоритет
над `secret.py`. Токены не публикуйте. Обычный access token истекает;
refresh token позволяет SDK обновлять его автоматически, пока доступ не отозван.

При **App folder** путь API `/For_to-do` соответствует папке
`Apps/<имя приложения>/For_to-do` в Dropbox (локализованное имя Apps может
отличаться). Логин и пароль внутри дневника остаются отдельными.
Используется официальный Python SDK `dropbox==12.0.2`.
Подробнее: [OAuth Dropbox](https://developers.dropbox.com/oauth-guide).

Для новой установки выберите собственную длинную секретную фразу.
**Если у вас уже есть сохранения, используйте прежнее значение фразы.**
Её замена сделает существующие зашифрованные данные и резервные копии
недоступными. Сохраните приватную копию `secret.py`; на устройствах,
синхронизирующих один аккаунт, должны использоваться одинаковые настройки.

Запуск настольного приложения:

```powershell
.\.venv\Scripts\python.exe main.py
```

Запускайте из корня проекта: локальные сохранения и настройки создаются
относительно рабочей папки. На первом запуске облачным функциям понадобится
интернет. Без входа в аккаунт можно работать с локальными делами.

В Linux/macOS создание окружения выполняется так же, а установка и запуск —
через `.venv/bin/python`; шаблон скопируйте командой
`cp secret.example.py secret.py`. Настольная сборка `.exe` предназначена для Windows.

## Хранение данных и секретов

На компьютере данные находятся в `saves/`, настройки — в `settings/`.
Эти папки создаются автоматически и исключены из Git вместе с `secret.py`.
Реальные значения секретов не входят в шаблон `secret.example.py`.
Шифрование файлов дел аккаунта можно включать и отключать в настройках
безопасности; старые бэкапы сохраняют свой исходный формат.

В веб-режиме локальные данные и настройки принадлежат браузеру посетителя
и сохраняются через `page.shared_preferences`. Очистка хранилища браузера
удалит локальные данные. Браузерные уведомления отключены; на настольной
платформе используются уведомления Plyer. Дополнительные Android-плагины
не входят в зависимости настольной и веб-версий.

Текущая схема облака использует общий аккаунт Dropbox и каталог аккаунта с именем
`<логин>_<пароль>`. Учитывайте это ограничение при использовании аккаунтов:
их пароли присутствуют в именах облачных папок.

### Общие группы

В меню «⋮» группы дел или заметок выберите «Сделать группу общей» и задайте пароль.
После успешной загрузки рядом с группой появится значок подключения.
На другом устройстве откройте «Авторизация» → «Общие группы», введите
исходное название группы и её пароль, затем нажмите «Подключить общую группу».
Тип группы определяется автоматически. В этом же разделе перечислены уже подключённые группы. Вход в личный аккаунт
для подключения общей группы не обязателен.

Облачный каталог `/For_to-do/Shared-Groups/<название>_<пароль>` содержит
только `tasks.json`. Для группы дел в нём хранятся обычные дела с их отметками,
датами и вложениями; для группы заметок — объект с типом `notes` и списком заметок
с текстом, датами и вложениями. Правила повторений, отложенные дела и дела,
созданные расписанием, остаются личными, как и настройки отображения группы.
Сведения о подключении сохраняются в локальном `groups.json` (в веб-версии —
в хранилище браузера) и синхронизируются вместе с личным аккаунтом, если выполнен вход.
Общие дела и заметки загружаются из общей папки группы; в личный аккаунт
попадают сведения о подключении и настройки отображения. Переименование подключённой группы меняет только её локальное
название; для нового подключения нужно исходное название.

Правки отправляются в фоне; чужие изменения приходят при запуске, ручном
обновлении или автообновлении открытого списка. Офлайн-правки сохраняются
до следующей успешной синхронизации. Изменения разных записей и разных полей
одной записи объединяются; при конфликте одного поля применяется отправляемая
локальная правка. Удалённая другим участником запись восстанавливается,
если одновременно была изменена локально. Пункт «Отключить» убирает группу
из ваших сохранений, сохраняя общие дела и заметки в облаке.

Общий файл группы зашифрован независимо от настройки шифрования личного аккаунта.
Пароль общей группы входит в имя облачной папки, как и пароль личного аккаунта;
не используйте для общей группы пароль от других сервисов. Название и пароль
не должны содержать `/ \\ : * ? " < > |` и пробельные символы по краям.

### Перенос существующих облачных данных

Смена провайдера в коде не переносит файлы автоматически. До входа в существующий
аккаунт перенесите прежнюю папку `/For_to-do` из MEGA или Яндекс Диска целиком
в Dropbox: при App folder — в `Apps/<имя приложения>/For_to-do`.
Сохраните имена папок аккаунтов, `security.json`, файлы секций и `backups`.
Если использовали локальную копию с экранированными именами, восстановите
исходные имена по `_cloud_download_manifest.json`; сам манифест не загружайте.

В существующий `secret.py` добавьте `DROPBOX_*` из шаблона, сохранив прежний
`ENCRYPTION_KEYWORD`. Настройки `MEGA_*` и `YANDEX_DISK_TOKEN` больше не используются.
Отметки прежнего провайдера не подтверждают загрузку в Dropbox.
Dropbox не различает регистр в именах: перед переносом проверьте, что нет
папок аккаунтов, различающихся только регистром. Имена также должны соответствовать
[ограничениям Dropbox](https://help.dropbox.com/organize/file-names).

## Веб-режим

По умолчанию `python main.py` открывает настольное приложение. Для запуска
в браузере в вызове `ft.run(...)` в конце `main.py` раскомментируйте:

```python
view=ft.AppView.WEB_BROWSER,
host=_host,
port=_port,
```

После этого адрес и порт задаются переменными окружения `ND_HOST`
(по умолчанию `0.0.0.0`) и `ND_PORT` (по умолчанию `8550`). Например,
для локальной проверки в PowerShell:

```powershell
$env:ND_HOST = "127.0.0.1"
$env:ND_PORT = "8550"
.\.venv\Scripts\python.exe main.py
```

Откройте `http://127.0.0.1:8550`. Инструкция для VPS находится в
[DEPLOY.md](DEPLOY.md). `secret.py` нужно отдельно разместить на сервере.
Переменная `ND_ASSETS_DIR` позволяет указать другую папку ресурсов.

## Сборка для Windows

Сначала настройте `secret.py`, затем установите зависимости сборки:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe build_windows.py
```

Результат — папка `dist/To-do list` с `To-do list.exe`; для переноса приложения
нужна вся папка. Для одного исполняемого файла:

```powershell
.\.venv\Scripts\python.exe build_windows.py --onefile
```

Подробности — в [BUILD_WINDOWS.md](BUILD_WINDOWS.md).
**PyInstaller включает импортируемый `secret.py` в сборку.** Готовый `.exe`
с вашими токенами Dropbox и ключом предназначен для личного использования:
не загружайте его в публичные GitHub Releases. `build/` и `dist/`
исключены из Git.

## Пересборка APK

При пересборке APK обновляйте `main.py` и целиком папки `Backend/`,
`Frontend/` и `assets/` в каталоге, из которого выполняется сборка.
Функция поиска ресурсов находится в `Backend/app_paths.py`: приложение
не зависит от отдельного `app_paths.py` в корне. Для ресурсов сборки Flet
используется `FLET_ASSETS_DIR`; явный `ND_ASSETS_DIR` имеет приоритет.
Сохраните прежний `secret.py` с настройками вашего приложения.

## Проверки

После установки зависимостей и настройки `secret.py`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

Облачные тесты используют подменённый клиент, не обращаясь к настоящему Dropbox.
О резервных копиях и отдельной проверке облака — в [BACKUPS.md](BACKUPS.md).

## Структура проекта

```text
Backend/                 Данные, шифрование, синхронизация и уведомления
Frontend/                Интерфейс и темы Flet
assets/                  Иконки и шрифты с файлами лицензий
tests/                   Автоматические проверки
main.py                  Точка входа
Backend/app_paths.py     Пути к ресурсам исходников и сборки
app_paths.py             Совместимость со старыми импортами
build_windows.py         Сборка приложения через PyInstaller
secret.example.py        Публичный шаблон настроек
secret.py                Локальные секреты, исключён из Git
requirements.txt         Зависимости приложения
requirements-build.txt   Дополнительные зависимости сборки
```

## Перед публикацией на GitHub

Проверьте список файлов, которые Git предлагает добавить:

```powershell
git status --short
git check-ignore secret.py saves/ settings/ build/ dist/
```

В репозитории должен быть `secret.example.py`, а реальные секреты,
пользовательские данные и сборки должны оставаться локально.
Если секреты уже попадали в опубликованную историю Git, одного
`.gitignore` недостаточно: удалите их из истории, отзовите скомпрометированные токены Dropbox
и получите новые.
Ключевое слово меняйте только после отдельного переноса зашифрованных данных.

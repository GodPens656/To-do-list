# To-do list — Дневник

Приложение для дел и заметок на Python с интерфейсом Flet. Поддерживает
локальное хранение, аккаунты и синхронизацию через MEGA.

## Возможности

- Дела и заметки в группах, отметка выполнения, редактирование и удаление.
- Отложенные дела и повторения по расписанию.
- Светлая и тёмная темы, настройка цветов, шрифтов и иконок.
- Пароль на вход в приложение.
- Шифрование локальных и облачных данных с помощью AES-256-GCM.
- Автоматические и ручные резервные копии в облаке.
- Настольный интерфейс и веб-режим с хранением данных посетителя в браузере.

## Установка и запуск

Проверено в Windows с Python 3.13.5. Версии основных зависимостей закреплены
в `requirements.txt` по рабочему окружению проекта.

После клонирования репозитория откройте терминал в его корневой папке:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item secret.example.py secret.py
```

Откройте `secret.py` и заполните значения:

| Настройка | Назначение |
| --- | --- |
| `MEGA_EMAIL` | Email общего аккаунта MEGA, на котором хранятся облачные данные. |
| `MEGA_PASSWORD` | Пароль этого аккаунта MEGA. |
| `MEGA_MFA_CODE` | Текущий одноразовый код, если в MEGA включена двухфакторная авторизация; иначе пустая строка. |
| `ENCRYPTION_KEYWORD` | Непустая секретная фраза для шифрования и расшифровки данных. |

**Получать API-ключ MEGA не нужно.** Разработчик официального SDK
[подтвердил, что AppKey больше не требуется](https://github.com/meganz/sdk/issues/2706).
Создайте аккаунт на [mega.nz](https://mega.nz/), подтвердите email и укажите
его email/пароль в настройках выше. Приложение создаёт каталог `/For_to-do`
в этом хранилище; логин и пароль аккаунта внутри дневника остаются отдельными.
Используется Python-клиент `mega.py-v2==2.1.0`, установка MEGAcmd не требуется.
Все значения `MEGA_*` можно задать переменными окружения, они имеют приоритет
над `secret.py`. Пароль передаётся без удаления пробелов.
При включённой 2FA задавайте свежий `MEGA_MFA_CODE` перед запуском:
код нужен при первом облачном запросе каждого процесса; сессия держится
в памяти до закрытия процесса. При повторном входе после отзыва сессии
также понадобится свежий код.

Для новой установки выберите собственную длинную секретную фразу.
**Если у вас уже есть сохранения, используйте прежнее значение фразы.**
Её замена сделает существующие зашифрованные данные и резервные копии
недоступными. Сохраните приватную копию `secret.py`; на устройствах,
синхронизирующих один аккаунт, должны использоваться одинаковые настройки.

Запуск настольного приложения:

```powershell
.\.venv\Scripts\python.exe main.py
```

Запускайте из корня проекта: локальные сохранения и настройки создаются
относительно рабочей папки. На первом запуске облачным функциям понадобится
интернет. Без входа в аккаунт можно работать с локальными делами.

В Linux/macOS создание окружения выполняется так же, а установка и запуск —
через `.venv/bin/python`; шаблон скопируйте командой
`cp secret.example.py secret.py`. Настольная сборка `.exe` предназначена для Windows.

## Хранение данных и секретов

На компьютере данные находятся в `saves/`, настройки — в `settings/`.
Эти папки создаются автоматически и исключены из Git вместе с `secret.py`.
Реальные значения секретов не входят в шаблон `secret.example.py`.
Шифрование файлов дел аккаунта можно включать и отключать в настройках
безопасности; старые бэкапы сохраняют свой исходный формат.

В веб-режиме локальные данные и настройки принадлежат браузеру посетителя
и сохраняются через `page.shared_preferences`. Очистка хранилища браузера
удалит локальные данные. Браузерные уведомления отключены; на настольной
платформе используются уведомления Plyer. Дополнительные Android-плагины
не входят в зависимости настольной и веб-версий.

Текущая схема облака использует общий аккаунт MEGA и каталог аккаунта с именем
`<логин>_<пароль>`. Учитывайте это ограничение при использовании аккаунтов:
их пароли присутствуют в именах облачных папок.

### Переход с Яндекс Диска

Перед первым запуском новой версии перенесите исходную папку `/For_to-do`
с Яндекс Диска в корень MEGA целиком, включая папки аккаунтов, `security.json`
и `backups`. Сохраните исходные имена папок и байты файлов. Это можно сделать
через веб-интерфейсы хранилищ; автоматический перенос старого облака не выполняется.
Если локальная копия создана `download_cloud.py`, имена для Windows могли быть
закодированы: восстановите исходные имена по `_cloud_download_manifest.json`
и не загружайте сам манифест как данные аккаунта.
В существующий `secret.py` добавьте настройки `MEGA_*` из шаблона, сохранив
прежний `ENCRYPTION_KEYWORD`. Прежний `YANDEX_DISK_TOKEN` больше не используется.
Отметки синхронизации Яндекс Диска не считаются подтверждением загрузки в MEGA.

## Веб-режим

По умолчанию `python main.py` открывает настольное приложение. Для запуска
в браузере в вызове `ft.run(...)` в конце `main.py` раскомментируйте:

```python
view=ft.AppView.WEB_BROWSER,
host=_host,
port=_port,
```

После этого адрес и порт задаются переменными окружения `ND_HOST`
(по умолчанию `0.0.0.0`) и `ND_PORT` (по умолчанию `8550`). Например,
для локальной проверки в PowerShell:

```powershell
$env:ND_HOST = "127.0.0.1"
$env:ND_PORT = "8550"
.\.venv\Scripts\python.exe main.py
```

Откройте `http://127.0.0.1:8550`. Инструкция для VPS находится в
[DEPLOY.md](DEPLOY.md). `secret.py` нужно отдельно разместить на сервере.
Переменная `ND_ASSETS_DIR` позволяет указать другую папку ресурсов.

## Сборка для Windows

Сначала настройте `secret.py`, затем установите зависимости сборки:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe build_windows.py
```

Результат — папка `dist/Dnevnik` с `Dnevnik.exe`; для переноса приложения
нужна вся папка. Для одного исполняемого файла:

```powershell
.\.venv\Scripts\python.exe build_windows.py --onefile
```

Подробности — в [BUILD_WINDOWS.md](BUILD_WINDOWS.md).
**PyInstaller включает импортируемый `secret.py` в сборку.** Готовый `.exe`
с вашими данными входа MEGA и ключом предназначен для личного использования:
не загружайте его в публичные GitHub Releases. `build/` и `dist/`
исключены из Git.

## Пересборка APK

При пересборке APK обновляйте `main.py` и целиком папки `Backend/`,
`Frontend/` и `assets/` в каталоге, из которого выполняется сборка.
Функция поиска ресурсов находится в `Backend/app_paths.py`: приложение
не зависит от отдельного `app_paths.py` в корне. Для ресурсов сборки Flet
используется `FLET_ASSETS_DIR`; явный `ND_ASSETS_DIR` имеет приоритет.
Сохраните прежний `secret.py` с настройками вашего приложения.

## Проверки

После установки зависимостей и настройки `secret.py`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

Облачные тесты используют подменённый клиент, не обращаясь к настоящему MEGA.
О резервных копиях и отдельной проверке облака — в [BACKUPS.md](BACKUPS.md).

## Структура проекта

```text
Backend/                 Данные, шифрование, синхронизация и уведомления
Frontend/                Интерфейс и темы Flet
assets/                  Иконки и шрифты с файлами лицензий
tests/                   Автоматические проверки
main.py                  Точка входа
Backend/app_paths.py     Пути к ресурсам исходников и сборки
app_paths.py             Совместимость со старыми импортами
build_windows.py         Сборка приложения через PyInstaller
secret.example.py        Публичный шаблон настроек
secret.py                Локальные секреты, исключён из Git
requirements.txt         Зависимости приложения
requirements-build.txt   Дополнительные зависимости сборки
```

## Перед публикацией на GitHub

Проверьте список файлов, которые Git предлагает добавить:

```powershell
git status --short
git check-ignore secret.py saves/ settings/ build/ dist/
```

В репозитории должен быть `secret.example.py`, а реальные секреты,
пользовательские данные и сборки должны оставаться локально.
Если секреты уже попадали в опубликованную историю Git, одного
`.gitignore` недостаточно: удалите их из истории, смените пароль MEGA
и завершите скомпрометированные сессии.
Ключевое слово меняйте только после отдельного переноса зашифрованных данных.

# Обновления приложения через GitHub Releases

При каждом запуске нативного приложения Windows или Android в фоне проверяется
[последний стабильный релиз](https://github.com/GodPens656/To-do-list/releases/latest).
Проверка не требует аккаунта GitHub и не блокирует интерфейс. Нет интернета,
релизов или подходящего файла — приложение продолжает работу без предупреждения.
На сайте проверка отключена: там версию обновляет владелец сервера.

Если тег релиза новее установленной версии, после загрузки приложения,
разблокировки и принятия примечаний появляется диалог «Доступно обновление»:

- **Позже** — закрыть предложение до следующего запуска.
- **Скачать** — открыть прямую загрузку сборки для устройства в системном браузере.
  Android получает APK; Windows — EXE, MSI или ZIP (в этом порядке предпочтения).
  Установку или распаковку пользователь выполняет после скачивания.

Текущая версия задаётся в одном месте: `Backend/version.py`, константа
`APP_VERSION`. Эта же версия показывается в настройках и используется проверкой.

## Публикация новой версии

1. Перед сборкой увеличьте `APP_VERSION`, например до `3.16.0`.
2. Соберите Windows-приложение и APK с этим исходным кодом. Для Android
   используйте прежний идентификатор пакета, прежний ключ подписи и больший
   `--build-number`, чтобы APK устанавливался поверх существующего приложения.
3. Создайте Release в `GodPens656/To-do-list` с тегом `3.16.0` или `v3.16.0`.
   Тег должен совпадать с версией в исходниках. Поддерживаются числовые версии
   до четырёх компонентов. Draft, prerelease и теги вроде `nightly` пропускаются.
4. Прикрепите APK и Windows-сборку как **Assets**, затем опубликуйте релиз
   как последний стабильный (**Latest**).

Существующие имена `To-Do.apk` и `To-do.list.2.zip` поддерживаются.
Для Windows-сборки в папку архивируйте **всю** папку приложения, включая `_internal`.
Для нескольких архитектур добавляйте к имени файла `x64`, `x86`, `arm64`
или `armv7`. Для Android рекомендуется один универсальный APK
(`To-do-universal.apk`); иначе выбирается файл с архитектурой устройства.
ZIP для других ОС должны содержать в имени `linux`, `macos`, `darwin`, `osx`
или `ios`, чтобы они не принимались за Windows-сборку.

Не нужно сохранять GitHub-токен в приложении: используется публичный API.
Автоматическая замена запущенного приложения и запуск установщика не выполняются.
